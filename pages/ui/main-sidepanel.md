`main.sidepanel` — это клиентское JavaScript-расширение Bitrix Framework для открытия страниц и содержимого в боковой панели. В API такую панель называют слайдером. Используйте расширение, когда нужно показать пользователю объект или форму без перехода с текущей страницы: карточку элемента, форму редактирования или настройки.

Основной API доступен через глобальный объект `BX.SidePanel.Instance`. JavaScript-код в браузере открывает боковую панель и управляет ею. PHP-код загружает расширение и готовит страницы, которые слайдер открывает во фрейме. Для таких страниц служит компонент `bitrix:ui.sidepanel.wrapper`.

## Подключить расширение

Если вы подключаете боковую панель из PHP, загрузите расширение `main.sidepanel`.

```php
\Bitrix\Main\UI\Extension::load('main.sidepanel');
```

После загрузки расширения используйте объект `BX.SidePanel.Instance` в JavaScript-коде страницы.

Если вы работаете в модульном JavaScript, импортируйте объект `SidePanel` из расширения.

```js
import { SidePanel } from 'main.sidepanel';

SidePanel.Instance.open('/crm/deal/details/15/', {
    width: 900,
});
```

## Открыть панель

Метод `BX.SidePanel.Instance.open(url, options)` открывает слайдер по URL.

Возвращаемое значение:

-  `true` — слайдер начал открываться.

-  `false` — слайдер не открылся. Возможные причины: URL пустой, сверху уже открыт слайдер с таким же URL или обработчик события запретил действие.

Если последний закрытый слайдер был кэширован и его URL совпадает с новым вызовом `open()`, менеджер использует этот экземпляр повторно.

**Пример.** Код открывает страницу `/crm/deal/details/15/` в слайдере шириной 900 пикселей. Слайдер не сохраняется после закрытия и не меняет URL текущей страницы.

```js
BX.SidePanel.Instance.open('/crm/deal/details/15/', {
    width: 900,
    cacheable: false,
    allowChangeHistory: false,
});
```

`url` должен быть непустой строкой.

Не добавляйте в `url` параметры `IFRAME` и `IFRAME_TYPE`. Слайдер добавляет к адресу `IFRAME=Y` и `IFRAME_TYPE=SIDE_SLIDER`, когда загружает страницу во фрейм. Как страница использует эти параметры, описано в разделе [Сделать страницу для слайдера](#slider-page).

### Передать содержимое без iframe

Если панель должна показать содержимое текущей страницы, передайте `contentCallback`. В этом режиме слайдер не загружает `iframe`, а использует результат функции как содержимое.

```js
BX.SidePanel.Instance.open('settings-panel', {
    width: 620,
    contentCallback: () => {
        const content = document.createElement('div');
        content.textContent = 'Настройки доступны без перехода на отдельную страницу.';

        return content;
    },
    cacheable: false,
});
```

Параметр `contentCallback` получает текущий слайдер и может вернуть DOM-узел, строку, объект с полем `html` или `Promise`, который завершится одним из этих значений.

В этом сценарии `url` остается идентификатором слайдера. Используйте стабильное значение, чтобы затем найти или закрыть слайдер через менеджер.

## Передать параметры слайдера

Параметр `options` в `open(url, options)` — объект настроек слайдера. Передавайте только те параметры, которые нужны конкретному сценарию.

|| **Параметр** | **Тип** | **Описание** ||
|| `width` | `number` | Наибольшая ширина панели в пикселях. Если значение не передано, панель занимает окно от отступа слева до правого края ||
|| `startPosition` | `string` | Сторона, с которой появляется слайдер. Допустимые значения `right`, `bottom` и `top`. По умолчанию `right` ||

|| `overlayOpacity` | `number` | Прозрачность затемнения от `0` до `100`. По умолчанию `40` ||
|| `overlayBgColor` | `string` | Цвет затемнения в формате `#RRGGBB`. По умолчанию `#000000` ||
|| `hideControls` | `boolean` | Скрывает стандартные элементы управления слайдера. По умолчанию `false` ||
|#

### Настроить загрузку через POST

Передайте `requestMethod: 'post'` и `requestParams`, если страницу внутри панели нужно открыть POST-запросом.

```js
BX.SidePanel.Instance.open('/reports/detail/', {
    width: 760,
    requestMethod: 'post',
    requestParams: {
        reportId: 42,
        mode: 'preview',
    },
});
```

### Добавить действия в панель

Чтобы показать в слайдере кнопку печати, открытия в новом окне или копирования ссылки, передайте параметры `printable`, `newWindowLabel` или `copyLinkLabel`.

```js
BX.SidePanel.Instance.open('/company/policy/', {
    width: 800,
    printable: true,
    newWindowLabel: true,
    copyLinkLabel: true,
});
```

Кнопка открытия в новом окне и кнопка копирования ссылки используют URL слайдера или значение `newWindowUrl`.

## Обработать события

Передайте обработчики в параметре `events`. Обработчик получает объект `SliderEvent`: `event.getSlider()` возвращает текущий слайдер, `event.denyAction()` запрещает открытие или закрытие.

**Пример.** Обработчик `onLoad` выводит в консоль URL загруженного слайдера. Обработчик `onClose` запрещает закрытие, если на странице есть несохраненные изменения. Обработчик `onCloseComplete` сбрасывает признак изменений после закрытия.

```js
BX.SidePanel.Instance.open('/crm/deal/details/15/', {
    width: 900,
    events: {
        onLoad: (event) => {
            const slider = event.getSlider();
            console.log(slider.getUrl());
        },
        onClose: (event) => {
            if (window.hasUnsavedChanges === true)
            {
                event.denyAction();
            }
        },
        onCloseComplete: () => {
            window.hasUnsavedChanges = false;
        },
    },
});
```

Событие `onClose` вызывается до начала закрытия и может запретить действие. Для кода после фактического закрытия используйте `onCloseComplete`.

Основные события:

-  `onOpen` — вызывается перед открытием. Обработчик может вызвать `denyAction()`.

-  `onOpenStart` — вызывается при начале открытия.

-  `onOpening` — вызывается при запуске анимации открытия.

-  `onLoad` — вызывается после загрузки `iframe` или содержимого из `contentCallback`.

-  `onReload` — вызывается после повторной загрузки `iframe`.

-  `onBeforeOpenComplete` и `onOpenComplete` — вызываются при завершении открытия.

-  `onClose` — вызывается перед закрытием. Обработчик может вызвать `denyAction()`.

-  `onCloseStart` — вызывается при начале закрытия.

-  `onClosing` — вызывается при запуске анимации закрытия.

-  `onBeforeCloseComplete` и `onCloseComplete` — вызываются при завершении закрытия.

-  `onDestroy` и `onDestroyComplete` — вызываются при уничтожении слайдера.

-  `onEscapePress` — вызывается при нажатии `Esc` внутри слайдера.

-  `onFrameFocus` — вызывается при переходе фокуса в `iframe` слайдера.

-  `onMaximizeStart` — вызывается при начале разворачивания свернутого слайдера.

-  `onMinimizeStart` — вызывается при начале сворачивания слайдера.

-  `onLayout` — вызывается при пересчете раскладки слайдера.

-  `onFullScreenEnter` — вызывается при переходе слайдера в полноэкранный режим.

-  `onFullScreenExit` — вызывается при выходе слайдера из полноэкранного режима.

-  `onMessage` — вызывается, когда слайдер получает сообщение от другого слайдера. Как подписаться на сообщения, описано в разделе [Принять сообщение](#receive-message).

Клавиша `Esc` закрывает слайдер только когда текущий слайдер находится поверх всплывающих окон и обработчики не запретили закрытие.

## Открывать ссылки автоматически

Метод `bindAnchors({ rules })` добавляет правила, по которым обычные ссылки открываются в боковой панели. Правило содержит массив условий `condition` и параметры `options`.

**Пример.** Ссылки на адреса вида `/crm/deal/details/<число>/` открываются в слайдере шириной 900 пикселей.

```js
BX.SidePanel.Instance.bindAnchors({
    rules: [
        {
            condition: [
                '/crm/deal/details/[0-9]+/',
            ],
            options: {
                width: 900,
                cacheable: false,
                allowChangeHistory: false,
            },
        },
    ],
});
```

Менеджер преобразует строковые условия в регулярные выражения без учета регистра. Если ссылка подходит под правило, менеджер отменяет обычный переход и вызывает `open(link.url, rule.options)`.

Правило принимает ключи из таблицы.

#|
|| **Параметр** | **Тип** | **Описание** ||
|| `condition` | `string[]` `RegExp[]` | Условия для адреса ссылки. Правило срабатывает, если адрес подходит хотя бы под одно условие ||
|| `options` | `object` `Function` | Параметры слайдера для `open()`. Функция получает объект ссылки и возвращает параметры ||
|| `stopParameters` | `string[]` | Query-параметры, при которых ссылка открывается обычным переходом ||
|| `allowCrossDomain` | `boolean` | Разрешает открывать в слайдере кросс-доменные ссылки. По умолчанию `false` ||
|| `mobileFriendly` | `boolean` | Разрешает открывать ссылки в слайдере в мобильном браузере. По умолчанию `false` ||
|| `validate` | `Function` | Дополнительная проверка ссылки. Функция получает объект ссылки. Если она вернула `false`, ссылка открывается обычным переходом ||
|| `handler` | `Function` | Обработчик клика вместо `open()`. Получает событие клика и объект ссылки. С этим ключом менеджер не отменяет обычный переход ||
|| `forceAnchorBinding` | `boolean` | Оставляет правило в работе после вызова `disableAnchorBinding()` ||
|#

Объект ссылки содержит адрес `url`, элемент ссылки `anchor`, значение атрибута `target` и результат совпадения адреса с условием `matches`.

Ссылка открывается обычным переходом, если у нее или у элемента, по которому кликнули, есть атрибут `data-slider-ignore-autobinding`.

Параметр `stopParameters` исключает ссылки с указанными query-параметрами.

**Пример.** Ссылки на адреса вида `/tasks/task/view/<число>/` открываются в слайдере, кроме ссылок с параметром `IFRAME` или `print` в адресе.

```js
BX.SidePanel.Instance.bindAnchors({
    rules: [
        {
            condition: [
                '/tasks/task/view/[0-9]+/',
            ],
            stopParameters: [
                'IFRAME',
                'print',
            ],
            options: {
                width: 820,
            },
        },
    ],
});
```

Чтобы временно отключить автоматическую обработку ссылок, вызовите `disableAnchorBinding()`. Метод `enableAnchorBinding()` включает обработку снова. Правила с `forceAnchorBinding: true` работают и при отключенной обработке.

```js
BX.SidePanel.Instance.disableAnchorBinding();
BX.SidePanel.Instance.enableAnchorBinding();
```

## Управлять открытыми панелями

`BX.SidePanel.Instance` хранит стек открытых слайдеров. Верхний слайдер считается текущим.

**Пример.** Код получает верхний слайдер и перезагружает его.

```js
const slider = BX.SidePanel.Instance.getTopSlider();

if (slider)
{
    slider.reload();
}
```

Основные методы менеджера:

#|
|| **Метод** | **Что делает** ||
|| `open(url, options)` | Открывает слайдер ||
|| `maximize(url, options)` | Открывает слайдер. Если на странице есть панель свернутых слайдеров, слайдер разворачивается из нее ||
|| `close(immediately, callback)` | Закрывает верхний слайдер ||
|| `closeAll(immediately)` | Закрывает все открытые слайдеры сверху вниз ||
|| `minimize(immediately, callback)` | Сворачивает верхний слайдер в панель свернутых слайдеров. Панель выводит компонент `bitrix:main.sidepanel.toolbar`. Если панели на странице нет, метод закрывает слайдер ||
|| `reload()` | Перезагружает верхний слайдер ||
|| `destroy(url)` | Уничтожает слайдер по URL ||
|| `getTopSlider()` | Возвращает верхний слайдер или `null` ||
|| `getSlider(url)` | Возвращает открытый слайдер по URL или `null` ||
|| `getOpenSliders()` | Возвращает массив открытых слайдеров ||
|| `getOpenSlidersCount()` | Возвращает количество открытых слайдеров ||
|| `hide()` и `unhide()` | Скрывают и возвращают открытые слайдеры без уничтожения ||
|| `enterFullScreen()` | Переводит браузер в полноэкранный режим для верхнего слайдера ||
|| `exitFullScreen()` | Выходит из полноэкранного режима ||
|#


Метод `close()` работает с верхним слайдером. Если нужно закрыть конкретный слайдер, получите его через `getSlider(url)` и вызовите `close()` у самого слайдера.

```js
const slider = BX.SidePanel.Instance.getSlider('/crm/deal/details/15/');

if (slider)
{
    slider.close();
}
```

## Передавать сообщения между слайдерами

Менеджер передает сообщения между слайдерами и основной страницей. Источником может быть URL слайдера, объект `Window` или экземпляр `Slider`.

Методы принимают три аргумента: источник сообщения, идентификатор события и объект с данными.

#|
|| **Метод** | **Куда отправляет сообщение** ||
|| `postMessage(source, eventId, data)` | В предыдущий слайдер. Если предыдущего слайдера нет, сообщение получает основная страница ||
|| `postMessageAll(source, eventId, data)` | Во все открытые слайдеры, кроме слайдера-источника, и на основную страницу ||
|| `postMessageTop(source, eventId, data)` | На основную страницу ||
|#

**Пример.** Код берет верхний слайдер и от его имени отправляет на основную страницу сообщение `deal-updated` с идентификатором сделки.

```js
const slider = BX.SidePanel.Instance.getTopSlider();

if (slider)
{
    BX.SidePanel.Instance.postMessageTop(slider, 'deal-updated', {
        id: 15,
    });
}
```

На странице внутри слайдера передайте источником объект `window`. Во фрейме объект `BX.SidePanel.Instance` ссылается на менеджер верхнего окна, а менеджер находит слайдер, во фрейме которого открыта страница. Для этого загрузите на странице расширение `main.sidepanel`.

**Пример.** Страница внутри слайдера отправляет сообщение `deal-updated` в предыдущий слайдер. Если предыдущего слайдера нет, сообщение получает основная страница.

```js
BX.SidePanel.Instance.postMessage(window, 'deal-updated', {
    id: 15,
});
```

Если источник не совпадает ни с одним открытым слайдером, методы ничего не отправляют. Со страницы, которая открыта не в слайдере, сообщение не уйдет.

Используйте сообщения, когда содержимое внутри панели должно уведомить внешнюю страницу или соседние слайдеры об изменении данных.

### Принять сообщение {#receive-message}

Чтобы получить сообщение, подпишитесь на событие `SidePanel.Slider:onMessage` на той странице, куда метод отправки доставляет сообщение:

-  на основной странице — сообщения `postMessageTop()`, `postMessageAll()` и `postMessage()`, если перед слайдером-источником не открыт другой слайдер,

-  на странице внутри слайдера — сообщения `postMessageAll()` и `postMessage()`, если этот слайдер — предыдущий для слайдера-источника.

Страница кросс-доменного слайдера, открытого с параметром `allowCrossOrigin`, такие сообщения не получает.

Обработчик получает объект сообщения `BX.SidePanel.MessageEvent`. Данные сообщения возвращают методы этого объекта.

| Метод | Что возвращает |
|---|---|
| `getEventId()` | Идентификатор события из второго аргумента метода отправки. Если передана пустая строка, метод возвращает `null` |
| `getData()` | Данные из третьего аргумента метода отправки |
| `getSender()` | Слайдер, который отправил сообщение |
| `getSlider()` | Слайдер, которому адресовано сообщение. Для основной страницы метод возвращает `null` |

Подписка на основной странице получает и сообщения, которые менеджер адресует слайдерам. Метод `postMessageAll()` вызывает обработчик отдельно для каждого открытого слайдера, кроме слайдера-источника, и еще раз для основной страницы. Чтобы обработать только сообщения для основной страницы, проверьте, что `getSlider()` вернул `null`.

Функция `BX.addCustomEvent()` подписывает обработчик на событие по имени и передает ему объект сообщения первым аргументом.

**Пример.** Основная страница получает сообщение `deal-updated` и выводит в консоль идентификатор сделки.

```js
BX.addCustomEvent('SidePanel.Slider:onMessage', (event) => {
    if (event.getSlider() !== null || event.getEventId() !== 'deal-updated')
    {
        return;
    }

    console.log(event.getData().id);
});
```

В модульном коде подпишитесь через `EventEmitter` из расширения [main.core.events](./main-core.md#rabotat-s-sobytiyami). Обработчик получает объект события `BaseEvent`, а объект сообщения лежит первым элементом массива `event.getCompatData()`.

**Пример.** Страница внутри слайдера получает сообщение `deal-updated` и выводит в консоль идентификатор сделки.

```js
import { EventEmitter } from 'main.core.events';

EventEmitter.subscribe('SidePanel.Slider:onMessage', (event) => {
    const [messageEvent] = event.getCompatData();
    if (messageEvent.getEventId() !== 'deal-updated')
    {
        return;
    }

    console.log(messageEvent.getData().id);
});
```

Если слайдер открываете вы, передайте обработчик `onMessage` в параметре `events` метода `open()`. Обработчик получит сообщения, адресованные этому слайдеру.

## Сделать страницу для слайдера {#slider-page}

Метод `open()` загружает страницу во фрейм и добавляет к ее адресу параметры `IFRAME=Y` и `IFRAME_TYPE=SIDE_SLIDER`. Компонент-обертка `bitrix:ui.sidepanel.wrapper` из модуля `ui` выводит во фрейме нужный компонент на отдельной HTML-странице без шаблона сайта.

Обертка работает в режиме слайдера, если в запросе есть параметр `IFRAME=Y` или в параметрах обертки передано `IFRAME_MODE => true`. Основные параметры обертки задают содержимое, поведение вне слайдера, вид страницы и действия после сохранения. Полный список параметров находится в методе `executeComponent()` файла `/bitrix/components/bitrix/ui.sidepanel.wrapper/class.php`.

### Подключить обертку

Создайте публичную страницу. Подключите на ней пролог `header.php`, вызовите обертку и подключите эпилог `footer.php`. Имя компонента для слайдера передайте в параметре `POPUP_COMPONENT_NAME`, а его параметры — в `POPUP_COMPONENT_PARAMS`.

**Пример.** Страница `/orders/edit.php` выводит компонент редактирования заказа `vendor:order.edit` и передает ему идентификатор заказа из параметра адреса `id`.

```php
<?php

use Bitrix\Main\Context;

require $_SERVER['DOCUMENT_ROOT'] . '/bitrix/header.php';

$request = Context::getCurrent()->getRequest();

$APPLICATION->IncludeComponent(
    'bitrix:ui.sidepanel.wrapper',
    '',
    [
        'POPUP_COMPONENT_NAME' => 'vendor:order.edit',
        'POPUP_COMPONENT_TEMPLATE_NAME' => '',
        'POPUP_COMPONENT_PARAMS' => [
            'ORDER_ID' => (int)$request->get('id'),
        ],
    ]
);

require $_SERVER['DOCUMENT_ROOT'] . '/bitrix/footer.php';
```

Откройте страницу в слайдере методом `open()`. Параметры `IFRAME` и `IFRAME_TYPE` в адрес не добавляйте.

```js
BX.SidePanel.Instance.open('/orders/edit.php?id=1', {
    width: 900,
});
```

В слайдере обертка выполняет три действия:

-  сбрасывает уже выведенную часть шаблона сайта и выводит собственную HTML-страницу с компонентом,

-  загружает расширение `main.sidepanel`, поэтому на странице доступен объект `BX.SidePanel.Instance`,

-  подключает эпилог и завершает выполнение скрипта.

В слайдере обертка завершает скрипт, поэтому код страницы после ее вызова не выполняется. Готовьте данные для компонента до вызова `IncludeComponent()`.

Содержимое страницы задают четыре параметра.

| Параметр | Тип | Описание |
|---|---|---|
| `POPUP_COMPONENT_NAME` | `string`, `array` | Имя компонента, который выводит обертка. Если передать массив имен, обертка выведет компоненты подряд в порядке массива |
| `POPUP_COMPONENT_TEMPLATE_NAME` | `string`, `array` | Шаблон компонента. Для массива компонентов передайте массив шаблонов в том же порядке. Строка задает один шаблон для всех компонентов |
| `POPUP_COMPONENT_PARAMS` | `array` | Параметры компонента. Для массива компонентов передайте массив массивов параметров в том же порядке |
| `POPUP_COMPONENT_PARENT` | `CBitrixComponent`, `false` | Родительский компонент. Если обертку вызывает шаблон другого компонента, передайте объект этого компонента. По умолчанию `false` |

### Настроить поведение вне слайдера

Страницу для слайдера можно открыть и напрямую, по ссылке или из адресной строки браузера. Что обертка покажет в этом случае, задают четыре параметра.

| Параметр | Тип | Описание |
|---|---|---|
| `PAGE_MODE` | `bool` | Со значением `true` выводит компонент внутри шаблона сайта, как обычную страницу. Со значением `false` показывает индикатор загрузки и открывает эту же страницу в слайдере. Если адрес подходит под правило из `bindAnchors()`, слайдер получает параметры этого правила. По умолчанию `true` |
| `PAGE_MODE_OFF_BACK_URL` | `string`, `null` | Адрес, на который браузер переходит после закрытия слайдера при `PAGE_MODE => false`. Со значением `null` браузер остается на странице. По умолчанию `/` |
| `IFRAME_MODE` | `bool` | Со значением `true` выводит страницу как содержимое слайдера без параметра `IFRAME=Y` в запросе. Если такую страницу могут открыть напрямую, передайте также `PREVENT_LOADING_WITHOUT_IFRAME => false`. Иначе обертка без конца перенаправляет браузер на тот же адрес |
| `PREVENT_LOADING_WITHOUT_IFRAME` | `bool` | Со значением `true` скрипт на странице с `IFRAME=Y` в адресе перенаправляет браузер на тот же адрес без параметра `IFRAME`, если страницу открыли не во фрейме. По умолчанию `true` |

### Проверить, открыта ли страница в слайдере

Обертка передает компоненту `IFRAME => true` и на обычной странице. Если вне слайдера компонент нужно вывести без обертки, проверьте параметры запроса сами.

**Пример.** Страница вызывает обертку только в слайдере. На обычной странице она выводит компонент напрямую, без параметра `IFRAME`.

```php
<?php

use Bitrix\Main\Context;

require $_SERVER['DOCUMENT_ROOT'] . '/bitrix/header.php';

$request = Context::getCurrent()->getRequest();
$params = [
    'ORDER_ID' => (int)$request->get('id'),
];

if ($request->get('IFRAME') === 'Y' && $request->get('IFRAME_TYPE') === 'SIDE_SLIDER')
{
    $APPLICATION->IncludeComponent(
        'bitrix:ui.sidepanel.wrapper',
        '',
        [
            'POPUP_COMPONENT_NAME' => 'vendor:order.edit',
            'POPUP_COMPONENT_TEMPLATE_NAME' => '',
            'POPUP_COMPONENT_PARAMS' => $params,
        ]
    );
}
else
{
    $APPLICATION->IncludeComponent('vendor:order.edit', '', $params);
}

require $_SERVER['DOCUMENT_ROOT'] . '/bitrix/footer.php';
```

### Настроить вид страницы

Отступы и фон страницы в слайдере задают три параметра.

| Параметр | Тип | Описание |
|---|---|---|
| `PLAIN_VIEW` | `bool` | Убирает отступы страницы и панель с заголовком. По умолчанию `false` |
| `USE_PADDING` | `bool` | Добавляет внутренние отступы области содержимого. Со значением `false` обертка выводит содержимое без отступов. По умолчанию `true` |
| `USE_BACKGROUND_CONTENT` | `bool` | Выводит фон области содержимого. Со значением `false` фон прозрачный. По умолчанию `true` |

Над содержимым обертка выводит [панель инструментов ui.toolbar](./ui-toolbar.md). Параметры, которые убирают или настраивают панель в слайдере, описаны в разделе [Вывести панель на своей странице](./ui-toolbar.md#component-params).

### Закрыть слайдер после сохранения

Обертка может закрыть слайдер и обновить предыдущую страницу после того, как форма в слайдере сохранила данные. Предыдущая страница — слайдер, открытый перед текущим, или основная страница, если такого слайдера нет.

Сценарий сохранения проходит четыре шага:

1. При первой загрузке страницы обертка запоминает в данных слайдера, какие действия нужно выполнить.

2. Форма отправляет POST-запрос. В ответе на POST-запрос обертка действия не выполняет.

3. Компонент сохраняет данные и перенаправляет браузер на страницу GET-запросом.

4. Страница снова загружается в том же слайдере, и обертка выполняет действия.

Обертка выполняет действия при каждой следующей загрузке страницы в том же слайдере, если запрос не POST.

Действия после сохранения задают четыре параметра.

| Параметр | Тип | Описание |
|---|---|---|
| `CLOSE_AFTER_SAVE` | `bool` | Закрывает слайдер. По умолчанию `false` |
| `RELOAD_GRID_AFTER_SAVE` | `bool`, `string` | Перезагружает [таблицу main.ui.grid](./main-ui-grid.md) на предыдущей странице. `true` — первую таблицу страницы, строка — таблицу с этим идентификатором, `'all'` — все таблицы. Если таблиц на странице нет, ничего не перезагружает. По умолчанию `false` |
| `RELOAD_PAGE_AFTER_SAVE` | `bool` | Перезагружает предыдущую страницу после закрытия слайдера. Работает только вместе с `CLOSE_AFTER_SAVE` и без `NOTIFICATION`. По умолчанию `false` |
| `NOTIFICATION` | `string`, `array` | Показывает в верхнем окне всплывающее уведомление после закрытия слайдера. Строка задает текст. Массив принимает ключи `content` — текст и `autoHideDelay` — время показа в миллисекундах, по умолчанию `5000`. Работает только вместе с `CLOSE_AFTER_SAVE` |

**Пример.** После сохранения страница редактирования заказа закрывает слайдер и перезагружает таблицу `orders_grid` на странице списка. Если страницу открыть не в слайдере, обертка откроет ее в слайдере, а после закрытия вернет пользователя на страницу `/orders/`.

```php
$APPLICATION->IncludeComponent(
    'bitrix:ui.sidepanel.wrapper',
    '',
    [
        'POPUP_COMPONENT_NAME' => 'vendor:order.edit',
        'POPUP_COMPONENT_TEMPLATE_NAME' => '',
        'POPUP_COMPONENT_PARAMS' => [
            'ORDER_ID' => (int)$request->get('id'),
        ],
        'CLOSE_AFTER_SAVE' => true,
        'RELOAD_GRID_AFTER_SAVE' => 'orders_grid',
        'PAGE_MODE' => false,
        'PAGE_MODE_OFF_BACK_URL' => '/orders/',
    ]
);
```

Перенаправление после сохранения выполняет компонент. Если компонент получил параметр `IFRAME`, добавьте в адрес перенаправления `IFRAME=Y`. Без этого параметра обертка не распознает слайдер при повторной загрузке.

**Пример.** Компонент `vendor:order.edit` после успешного сохранения перенаправляет браузер на страницу заказа и оставляет в адресе признак слайдера. В переменной `$orderId` — идентификатор сохраненного заказа.

```php
use Bitrix\Main\Web\Uri;

$uri = new Uri('/orders/edit.php');
$uri->addParams(['id' => $orderId]);
if ($this->arParams['IFRAME'] === true)
{
    $uri->addParams(['IFRAME' => 'Y']);
}

LocalRedirect($uri->getLocator());
```
