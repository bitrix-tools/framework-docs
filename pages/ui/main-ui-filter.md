`main.ui.filter` выводит строку поиска и набор полей фильтрации. Используйте компонент на страницах со списками, отчетами и таблицами, где пользователь должен выбрать условия, сохранить пресет и применить фильтр к данным.

Компонент отвечает только за интерфейс фильтра и сохранение пользовательских настроек. Серверный код страницы получает выбранные значения через `Bitrix\Main\UI\Filter\Options` или через слой `Bitrix\Main\Filter\Filter`, а затем сам применяет условия к ORM-запросу, массиву данных или другому источнику.

Если фильтр работает вместе с [таблицей `main.ui.grid`](./main-ui-grid.md), передайте один и тот же идентификатор в `FILTER_ID` и `GRID_ID`. Тогда фильтр сможет обновлять связанный грид после применения условий.

## Вывести фильтр

Передайте в компонент идентификатор фильтра и массив полей. Минимальное поле содержит `id` и `name`; если `type` не указан, поле работает как строковое.

Строку поиска компонент выводит сам, описывать ее в `FILTER` не нужно. Введенный текст сервер получает в ключе `FIND` — подробнее в разделе [Получить значения](#poluchit-znacheniya). Чтобы убрать строку поиска, передайте `'DISABLE_SEARCH' => true`.

**Пример.** Фильтр заказов со строкой поиска и двумя полями — списком статусов и датой создания.

```php
<?php

$filterId = 'orders_filter';

$APPLICATION->IncludeComponent(
    'bitrix:main.ui.filter',
    '',
    [
        'FILTER_ID' => $filterId,
        'FILTER' => [
            [
                'id' => 'STATUS',
                'name' => 'Статус',
                'type' => 'list',
                'items' => [
                    '' => 'Любой',
                    'new' => 'Новый',
                    'done' => 'Выполнен',
                ],
            ],
            [
                'id' => 'DATE_CREATE',
                'name' => 'Дата создания',
                'type' => 'date',
            ],
        ],
        'ENABLE_LABEL' => true,
    ]
);
```

Основные параметры вызова:

| Параметр | Тип | Описание |
|---|---|---|
| `FILTER_ID` | `string` | Обязательный идентификатор фильтра. Используйте уникальное значение для каждой страницы или логического списка, потому что по нему сохраняются пользовательские настройки |
| `GRID_ID` | `string` | Идентификатор грида. Передавайте его, если фильтр должен обновлять таблицу `main.ui.grid` |
| `FILTER` | `array` | Обязательный массив полей фильтра. Компонент преобразует поля в данные для интерфейса |
| `FILTER_PRESETS` | `array` | Массив пресетов фильтра |
| `ENABLE_LABEL` | `bool` | `true` включает подписи полей |

## Настроить поведение

Компонент поддерживает настройки интерфейса, которые влияют на внешний вид и сценарий работы.

| Параметр | Тип | Значение | Описание |
|---|---|---|---|
| `DISABLE_SEARCH` | `bool` | `true` | Отключает строку поиска |
| `ENABLE_LIVE_SEARCH` | `bool` | `true` | Применяет фильтр по мере ввода |
| `ENABLE_FIELDS_SEARCH` | `string` | `'Y'` | Включает поиск по названиям полей в настройках фильтра |
| `ENABLE_LABEL` | `bool` | `true` | Показывает подписи полей |
| `RESET_TO_DEFAULT_MODE` | `bool` | `true` | Возвращает фильтр к начальному состоянию при сбросе |
| `VALUE_REQUIRED_MODE` | `bool` | `true` | Включает режим, в котором фильтр может требовать значение |
| `COMPACT_STATE` | `bool` | `true` | Включает компактное состояние фильтра |
| `HEADERS_SECTIONS` | `array` | Непустой массив | Группирует поля по секциям. Поле привязывается к секции через `sectionId` |
| `RENDER_FILTER_INTO_VIEW` | `string` | Идентификатор области | Встраивает фильтр в указанную область |
| `RENDER_FILTER_INTO_VIEW_SORT` | `int` | Число сортировки | Задает сортировку фильтра внутри области |
| `MESSAGES` | `array` | Массив текстов | Заменяет пользовательские тексты интерфейса. Компонент использует только ключи, которые начинаются с `MAIN_UI_FILTER__` |
| `LIMITS` | `array` | Массив с `TITLE`, `DESCRIPTION` и `BUTTONS` | Показывает ограничение. Если задан заголовок ограничения, компонент отключает строку поиска |
| `RESTRICTED_FIELDS` | `array` | Непустой массив | Задает список ограниченных полей |

## Получить значения

После отправки формы получите значения фильтра на сервере и примените их к выборке.

```php
<?php

use Bitrix\Main\UI\Filter\Options;

$filterId = 'orders_filter';
$filterFields = [
    ['id' => 'STATUS', 'name' => 'Статус', 'type' => 'list'],
    ['id' => 'DATE_CREATE', 'name' => 'Дата создания', 'type' => 'date'],
];

$filterOptions = new Options($filterId);
$filter = $filterOptions->getFilter($filterFields);
$ormFilter = [];

if (!empty($filter['STATUS']))
{
    $ormFilter['=STATUS'] = $filter['STATUS'];
}

if (!empty($filter['DATE_CREATE_from']))
{
    $ormFilter['>=DATE_CREATE'] = $filter['DATE_CREATE_from'];
}

if (!empty($filter['DATE_CREATE_to']))
{
    $ormFilter['<=DATE_CREATE'] = $filter['DATE_CREATE_to'];
}

if (!empty($filter['FIND']))
{
    $ormFilter['%TITLE'] = $filter['FIND'];
}
```

Метод `Options::getFilter()` возвращает значения, которые пользователь выбрал в интерфейсе. Для полей с диапазоном компонент добавляет служебные ключи, например `_from`, `_to`, `_datesel` и `_numsel`. Используйте только те ключи, которые нужны вашему запросу.

Метод `getFilter()` возвращает текст строки поиска в ключе `FIND`, хотя такого поля в `FILTER` нет. Вместе с ним метод добавляет служебные ключи `PRESET_ID`, `FILTER_ID` и `FILTER_APPLIED`. Все четыре ключа появляются, только когда фильтр применен — пользователь ввел текст поиска или задал значение хотя бы одного поля. В остальных случаях `getFilter()` возвращает пустой массив, поэтому проверяйте ключи через `empty()` или `isset()`.

Метод `getValue()` класса `Bitrix\Main\Filter\Filter` удаляет служебные поля интерфейса и вызывает подготовку значений у провайдера. Используйте его, если страница уже построена на серверном слое `Bitrix\Main\Filter\Filter`. Для объекта фильтра нужен провайдер данных, поэтому не создавайте его только ради чтения значений из обычного компонента.

Что возвращает фильтр:

| Тип поля | Ключи в результате | Когда использовать |
|---|---|---|
| `string` | `ID_поля` | Для точного значения или поиска по строке |
| `textarea` | `ID_поля` | Для многострочного значения |
| `list` | `ID_поля` | Для выбранного значения списка. При множественном выборе значение обрабатывайте как набор выбранных вариантов |
| `number` | `ID_поля`, `ID_поля_from`, `ID_поля_to`, `ID_поля_numsel` | Для точного числа или диапазона |
| `date` | `ID_поля_from`, `ID_поля_to`, `ID_поля_datesel` | Для выбранного периода или ручного диапазона дат |
| `custom_date` | `ID_поля_days`, `ID_поля_months`, `ID_поля_years` | Для произвольного выбора дней, месяцев и лет |
| `entity_selector` | `ID_поля` | Для идентификатора выбранного объекта. Если включен `addEntityIdToResult`, значение содержит тип объекта и идентификатор элемента |

## Связать с гридом

Для связки с [таблицей `main.ui.grid`](./main-ui-grid.md) используйте один идентификатор для фильтра и таблицы. Фильтр только возвращает выбранные значения; серверный код сам преобразует их в условия выборки и строки грида.

После применения и сброса фильтр перезагружает связанный грид — отправляет POST-запрос с параметрами `apply_filter=Y` и `clear_nav=Y`. Чтобы выполнить свой код после применения, подпишитесь на событие фильтра — подробнее в разделе [Обработать события фильтра](#obrabotat-sobytiya-filtra).

В примере `$orders` — массив записей. В рабочем коде замените его выборкой из своего источника данных с учетом `$ormFilter`.

```php
<?php

use Bitrix\Main\UI\Filter\Options;

$gridId = 'orders_grid';
$filterFields = [
    ['id' => 'STATUS', 'name' => 'Статус', 'type' => 'list'],
];

$filterOptions = new Options($gridId);
$filter = $filterOptions->getFilter($filterFields);
$ormFilter = [];

if (!empty($filter['STATUS']))
{
    $ormFilter['=STATUS'] = $filter['STATUS'];
}

if (!empty($filter['FIND']))
{
    $ormFilter['%TITLE'] = $filter['FIND'];
}

$orders = [
    [
        'ID' => 1,
        'TITLE' => 'Заказ на доставку',
        'STATUS' => 'Новый',
    ],
];

$rows = [];
foreach ($orders as $order)
{
    $rows[] = [
        'id' => $order['ID'],
        'data' => [
            'ID' => $order['ID'],
            'TITLE' => $order['TITLE'],
            'STATUS' => $order['STATUS'],
        ],
    ];
}

$APPLICATION->IncludeComponent(
    'bitrix:main.ui.filter',
    '',
    [
        'FILTER_ID' => $gridId,
        'GRID_ID' => $gridId,
        'FILTER' => $filterFields,
    ]
);

$APPLICATION->IncludeComponent(
    'bitrix:main.ui.grid',
    '',
    [
        'GRID_ID' => $gridId,
        'COLUMNS' => [
            ['id' => 'ID', 'name' => 'ID', 'default' => true],
            ['id' => 'TITLE', 'name' => 'Название', 'default' => true],
            ['id' => 'STATUS', 'name' => 'Статус', 'default' => true],
        ],
        'ROWS' => $rows,
    ]
);
```

## Описать поля

Основные ключи поля:

| Ключ | Тип | Описание |
|---|---|---|
| `id` | `string` | Обязательный идентификатор поля. По нему значение возвращается в массиве фильтра |
| `name` | `string` | Обязательная подпись поля в интерфейсе |
| `type` | `string` | Тип поля. Если ключ не указан, используется строковое поле. Передавайте значение в нижнем регистре |
| `default` | `bool` | `true` показывает поле в фильтре по умолчанию |
| `items` | `array` | Варианты для списков. Для поля `list` передайте массив, где ключ станет значением фильтра, а значение массива — подписью в интерфейсе |
| `params` | `array` | Дополнительные параметры поля. Для списков в нем задают множественный выбор |
| `exclude` | `array` | Список подтипов даты, которые нужно убрать из выбора |
| `sectionId` | `string` | Идентификатор секции, если поля сгруппированы через `HEADERS_SECTIONS` |

### Строка и текст

Тип `string` подходит для короткого значения или поиска по части текста.

```php
<?php

$field = [
    'id' => 'TITLE',
    'name' => 'Название',
    'type' => 'string',
    'default' => true,
];
```

Тип `textarea` используйте для многострочного значения. Оба типа возвращают значение по ключу поля.

### Список

Тип `list` показывает выпадающий список. В `items` передайте массив вариантов, где ключ станет значением фильтра, а значение массива — подписью в интерфейсе.

```php
<?php

$field = [
    'id' => 'STATUS',
    'name' => 'Статус',
    'type' => 'list',
    'items' => [
        '' => 'Любой',
        'new' => 'Новый',
        'done' => 'Выполнен',
    ],
];
```

Для множественного выбора передайте ключ `multiple` со значением `'Y'` в массиве `params`.

```php
<?php

$field = [
    'id' => 'STATUS',
    'name' => 'Статус',
    'type' => 'list',
    'params' => [
        'multiple' => 'Y',
    ],
    'items' => [
        'new' => 'Новый',
        'progress' => 'В работе',
        'done' => 'Выполнен',
    ],
];
```

### Число

Тип `number` поддерживает точное значение и диапазон. При выборе диапазона фильтр возвращает ключи с постфиксами `_from` и `_to`.

```php
<?php

$field = [
    'id' => 'PRICE',
    'name' => 'Сумма',
    'type' => 'number',
];
```

### Дата

Тип `date` показывает готовые варианты периода и ручной ввод диапазона. Подтипы даты определены в `Bitrix\Main\UI\Filter\DateType`.

```php
<?php

use Bitrix\Main\UI\Filter\DateType;

$field = [
    'id' => 'DATE_CREATE',
    'name' => 'Дата создания',
    'type' => 'date',
    'exclude' => [
        DateType::LAST_60_DAYS,
        DateType::LAST_90_DAYS,
    ],
];
```

Если нужно выбирать время вместе с датой, передайте `time`.

```php
<?php

$field = [
    'id' => 'DATE_CREATE',
    'name' => 'Дата создания',
    'type' => 'date',
    'time' => true,
];
```

Тип `custom_date` используется для произвольного выбора дней, месяцев и лет. Компонент возвращает значения с постфиксами `_days`, `_months` и `_years`.

### Выбор объектов

Тип `entity_selector` подключает интерфейс выбора объектов через `ui.entity-selector`. Передайте настройки диалога в `params.dialogOptions`.

```php
<?php

$field = [
    'id' => 'RESPONSIBLE_ID',
    'name' => 'Ответственный',
    'type' => 'entity_selector',
    'params' => [
        'multiple' => 'Y',
        'dialogOptions' => [
            'context' => 'orders_filter',
            'entities' => [
                [
                    'id' => 'user',
                ],
            ],
        ],
    ],
];
```

Если в одном поле доступны объекты разных типов, передайте ключ `addEntityIdToResult` со значением `'Y'` в массиве `params`. Тогда значение сохранит идентификатор типа объекта и идентификатор выбранного элемента.

Без этого параметра фильтр возвращает идентификатор выбранного элемента.

Тип `dest_selector` подходит для выбора пользователей, подразделений и других адресатов через прежний селектор. Используйте его в существующих интерфейсах, где уже настроены параметры этого селектора.

Используйте тип `custom_entity`, если поле обрабатывает выбор своим JavaScript-кодом и само подставляет подпись выбранного значения. Если новый интерфейс может работать через `ui.entity-selector`, выбирайте `entity_selector`.

## Добавить пресеты

Пресет задает сохраненный набор значений фильтра. Передайте массив `FILTER_PRESETS`, где ключ — идентификатор пресета.

```php
<?php

$presets = [
    'active_orders' => [
        'name' => 'Активные заказы',
        'default' => true,
        'fields' => [
            'STATUS' => 'new',
            'DATE_CREATE_datesel' => 'CURRENT_MONTH',
        ],
    ],
];
```

Основные ключи пресета:

| Ключ | Тип | Описание |
|---|---|---|
| `name` | `string` | Обязательное название в меню пресетов |
| `default` | `bool` | `true` делает пресет выбранным по умолчанию |
| `fields` | `array` | Обязательные значения полей. Ключи должны совпадать с `id` полей или служебными ключами диапазонов |
| `disallow_for_all` | `bool` | Запрещает применять пресет для всех пользователей, если сценарий поддерживает общие пресеты |

{% note warning "" %}

Пользовательские настройки фильтра сохраняются по `FILTER_ID`. Если изменить идентификатор, ранее сохраненные пресеты и выбранные поля не применятся к новому фильтру.

{% endnote %}

## Управлять фильтром из JavaScript

На странице фильтр представлен объектом `BX.Main.Filter`. Компонент регистрирует объект в `BX.Main.filterManager` под значением `FILTER_ID`. Через этот объект и его API код страницы подставляет значения в поля, выбирает пресет и применяет фильтр без действий пользователя.

### Получить объект фильтра

Метод `BX.Main.filterManager.getById()` возвращает объект фильтра по значению `FILTER_ID`. Если фильтра с таким идентификатором на странице нет, метод возвращает `null`.

{% note warning "" %}

Компонент регистрирует фильтр в обработчике `BX.ready`. Получайте объект в своем обработчике `BX.ready` и подключайте скрипт после вызова компонента, потому что обработчики `BX.ready` выполняются в порядке подключения. Иначе `getById()` вернет `null`.

{% endnote %}

**Пример.** Скрипт получает объект фильтра `orders_grid` и его API.

```js
BX.ready(() => {
    const filter = BX.Main.filterManager.getById('orders_grid');
    if (!filter)
    {
        return;
    }

    const api = filter.getApi();
});
```

Сценарии раздела вызывают три метода объекта фильтра:

-  `getApi()` — возвращает объект `BX.Filter.Api` с методами управления фильтром. Метод создает объект при первом вызове и при повторных вызовах возвращает его же.

-  `getFilterFieldsValues()` — возвращает объект с текущими значениями полей формы. Текст строки поиска лежит в ключе `FIND`.

-  `resetFilter(withoutSearch)` — сбрасывает значения полей и выбранный пресет, затем применяет фильтр. Метод очищает строку поиска, если не передан `true`. Возвращает `BX.Promise`.

### Методы API

Методы `BX.Filter.Api` ничего не возвращают. Чтобы выполнить код после применения фильтра, подпишитесь на событие `BX.Main.Filter:apply` — подробнее в разделе [Обработать события фильтра](#obrabotat-sobytiya-filtra).

| Метод | Параметры | Что делает |
|---|---|---|
| `setFields(fields)` | `fields` — объект, где ключ — `id` поля, а значение — значение поля | Подставляет значения в поля формы и снимает выделение с пресетов. Фильтр не применяет. Если `fields` не объект, ничего не делает |
| `apply(analyticsLabel)` | `analyticsLabel` — необязательный объект, поля которого добавляются в метку аналитики запроса | Применяет значения, которые стоят в полях формы, и закрывает окно фильтра. Если окно фильтра в режиме редактирования, ничего не делает |
| `setFilter(filter, analyticsLabel)` | `filter` — объект с идентификатором пресета в ключе `preset_id`. `analyticsLabel` — необязательная метка аналитики | Выбирает пресет, подставляет его значения в поля и применяет фильтр |
| `extendFilter(fields, force, analyticsLabel)` | `fields` — объект, где ключ — `id` поля, а значение — значение поля. `force` — `true`, чтобы добавить значения к полям формы даже при выбранном пресете. `analyticsLabel` — необязательная метка аналитики | Добавляет значения к текущему фильтру и применяет его. Числовые значения приводит к строке |

### Подставить значения и применить фильтр

Метод `setFields()` меняет только поля формы. Чтобы фильтр сохранил значения и обновил данные, сразу после него вызовите `apply()`.

Правила для объекта `fields`:

-  Ключи — `id` полей из `FILTER`. Ключ, для которого в фильтре нет поля, метод пропускает.

-  Для поля `list` передайте ключ варианта из `items` строкой.

-  Объект заменяет весь набор значений полей. Поля, которых в нем нет, теряют заданные раньше значения. Текст строки поиска метод не меняет.

**Пример.** Функция оставляет в фильтре `orders_grid` только условие на статус «Новый» и применяет фильтр. Связанный грид перезагружается с новыми условиями.

```js
function showNewOrders()
{
    const filter = BX.Main.filterManager.getById('orders_grid');
    if (!filter)
    {
        return;
    }

    const api = filter.getApi();
    api.setFields({ STATUS: 'new' });
    api.apply();
}
```

Чтобы сохранить остальные условия, передайте в `setFields()` текущие значения из `getFilterFieldsValues()` вместе с новым значением поля. Тот же результат одним вызовом дает метод `extendFilter()` с параметром `force`, равным `true`.

### Добавить условие к текущему фильтру

Метод `extendFilter()` добавляет значения к уже выбранным условиям и применяет фильтр. Результат зависит от того, что выбрано в фильтре:

-  Без пресета или с системным пресетом «Фильтр» метод объединяет текущие значения полей с переданными.

-  С другим пресетом результат зависит от переданных полей. Если в пресете таких полей нет, метод оставляет пресет выбранным и добавляет значения к нему как дополнительные поля. Если поле уже задано в пресете, метод снимает выделение с пресета и применяет строку поиска и переданные значения, а остальные значения пресета теряются.

-  С `force`, равным `true`, метод объединяет значения так же, как без пресета, даже если выбран пресет. Выделение с пресета метод при этом снимает.

**Пример.** Функция добавляет к фильтру `orders_grid` условие на статус «Выполнен» и сохраняет остальные условия, даже если выбран пресет со статусом.

```js
function filterDoneOrders()
{
    const filter = BX.Main.filterManager.getById('orders_grid');
    if (!filter)
    {
        return;
    }

    filter.getApi().extendFilter({ STATUS: 'done' }, true);
}
```

### Выбрать пресет

Метод `setFilter()` выбирает пресет по идентификатору, подставляет его значения в поля и применяет фильтр. Идентификатор пресета — ключ массива `FILTER_PRESETS`.

Кроме пресетов из `FILTER_PRESETS`, компонент создает системный пресет «Фильтр» с идентификатором `default_filter`. В него входят поля из `FILTER` с ключом `'default' => true`. Это другой пресет, не тот, который ключ `default` в `FILTER_PRESETS` делает выбранным по умолчанию.

**Пример.** Функция выбирает пресет `active_orders` из раздела [Добавить пресеты](#dobavit-presety).

```js
function showActiveOrders()
{
    const filter = BX.Main.filterManager.getById('orders_grid');
    if (!filter)
    {
        return;
    }

    filter.getApi().setFilter({ preset_id: 'active_orders' });
}
```

## Обработать события фильтра

Фильтр вызывает глобальные события через `BX.onCustomEvent()`. Любой фильтр страницы вызывает одни и те же события, поэтому в обработчике сравнивайте первый аргумент с нужным `FILTER_ID`.

| Событие | Когда срабатывает | Аргументы |
|---|---|---|
| `BX.Main.Filter:beforeApply` | При применении и сбросе фильтра, до сохранения значений | `filterId`, `{ action }`, `filter`, `promise` |
| `BX.Main.Filter:apply` | При применении и сбросе фильтра, после сохранения значений | `filterId`, `{ action }`, `filter`, `promise`, `applyParams` |
| `BX.Filter.Search:input` | При изменении текста в строке поиска, если включен `ENABLE_LIVE_SEARCH` | `filterId`, `searchString` |
| `BX.Main.Filter:onApplyPreset` | При подстановке значений пресета в поля формы, в том числе из `setFields()` и `setFilter()` | `presetId`. Идентификатора фильтра в аргументах нет |
| `BX.Main.Filter:show` | При открытии окна фильтра | `filter` |
| `BX.Main.Filter:blur` | При закрытии окна фильтра клавишей Esc и при нажатии кнопки мыши вне фильтра | `filter` |

Аргументы событий применения:

-  `filterId` — значение `FILTER_ID` фильтра,

-  `action` — `'apply'` при применении и `'clear'` при сбросе,

-  `filter` — объект `BX.Main.Filter`,

-  `promise` — объект `BX.Promise`, который завершает применение фильтра,

-  `applyParams` — объект с ключом `autoResolve`.

Событие `BX.Main.Filter:beforeApply` срабатывает до того, как фильтр определит текущий пресет, поэтому обработчик может сменить пресет. Событие `BX.Main.Filter:apply` срабатывает после того, как компонент сохранил значения фильтра на сервере.

Событие `BX.Filter.Search:input` срабатывает сразу при вводе, кроме первого символа, введенного в пустую строку поиска. Сам фильтр применяется через 800 миллисекунд после последнего изменения строки поиска.

### Обновить свой список после применения

Если на странице есть грид с тем же `GRID_ID`, фильтр перезагружает его и завершает `promise` после ответа сервера. Если данные выводит свой код, подпишитесь на событие `BX.Main.Filter:apply` и запросите данные в обработчике.

Без грида фильтр завершает `promise` сразу после обработчиков. Чтобы завершить его после своего запроса, присвойте `applyParams.autoResolve` значение `false` и вызовите `promise.fulfill()` или `promise.reject()`.

{% note warning "" %}

Завершите `promise` в любом исходе запроса. Пока он не завершен, строка поиска не запускает новое применение фильтра.

{% endnote %}

**Пример.** Обработчик обновляет список заказов, когда пользователь применяет или сбрасывает фильтр `orders_filter`. Обработчик отключает автоматическое завершение, запрашивает данные действием контроллера и завершает `promise` после ответа.

```js
BX.addCustomEvent('BX.Main.Filter:apply', (filterId, data, filter, promise, applyParams) => {
    if (filterId !== 'orders_filter')
    {
        return;
    }

    applyParams.autoResolve = false;

    BX.ajax.runAction('example.Order.list')
        .then((response) => {
            // обновите список данными из response.data
            promise.fulfill();
        })
        .catch(() => {
            promise.reject();
        });
});
```

Действие контроллера читает условия через `Options::getFilter()`, как в разделе [Получить значения](#poluchit-znacheniya). К моменту события компонент уже сохранил новые значения.

### Подписаться через EventEmitter

Обработчик, подписанный через `BX.addCustomEvent()`, получает аргументы события отдельными параметрами. Обработчик, подписанный через `EventEmitter.subscribe()`, получает объект `BaseEvent`, а аргументы — массивом из метода `getData()`.

**Пример.** Обработчик в формате `BaseEvent` различает применение и сброс фильтра `orders_filter` до сохранения значений.

```js
import { EventEmitter } from 'main.core.events';

EventEmitter.subscribe('BX.Main.Filter:beforeApply', (event) => {
    const [filterId, { action }] = event.getData();
    if (filterId !== 'orders_filter')
    {
        return;
    }

    console.log(action === 'clear' ? 'Сброс фильтра' : 'Применение фильтра');
});
```
