Структура проекта на Bitrix Framework разделяет системные файлы, собственный код и загруженные файлы. Используйте эту схему после установки продукта, при создании нового функционала и при переносе доработок из ядра. Правильное расположение файлов отделяет изменения от системных файлов и упрощает обновление и поддержку проекта.

Корень сайта — каталог, в котором находятся системные папки и публичные страницы. Пути в статье начинаются с `/` от корня сайта, а не от корня файловой системы сервера.

## Основные папки и файлы

Выбирайте расположение файла по его назначению. Не переносите собственный код в системные папки и не записывайте файлы напрямую в `/upload/` в обход стандартных интерфейсов и API.

| Путь | Что содержит | Как изменять |
|---|---|---|
| [`/bitrix/`](#bitrix) | Ядро, системные модули, компоненты, шаблоны и настройки | Системные файлы не изменять. Разрешенные способы кастомизации описаны в статье [Как правильно и безопасно кастомизировать коробочные продукты](./how-customize.md) |
| [`/local/`](#local) | Собственные модули, компоненты, шаблоны, обработчики, маршруты и другие доработки | Создавать и изменять файлы проекта |
| [`/upload/`](#upload) | Файлы, которые загружают стандартные механизмы продукта | Сохранять, читать и удалять файлы через интерфейс или API |
| [`/index.php` и другие публичные файлы](#public) | Физические страницы и разделы сайта | Создавать страницы в корне сайта и его публичных разделах |

**Пример.** Сокращенная структура проекта с собственным модулем, обработчиками, маршрутами и публичным разделом:

```text
/
├── bitrix/
│   ├── modules/                 # Системные модули
│   ├── components/              # Системные компоненты
│   ├── templates/               # Системные шаблоны
│   ├── php_interface/           # Системные файлы инициализации
│   └── .settings.php            # Основная конфигурация ядра
├── local/
│   ├── modules/my.project/      # Собственный модуль
│   ├── components/my/           # Собственные компоненты
│   ├── templates/my_template/   # Шаблон сайта проекта
│   ├── php_interface/init.php   # Инициализация проекта
│   └── routes/web.php           # Маршруты проекта
├── upload/                      # Загруженные файлы
├── catalog/
│   └── index.php                # Индексный файл раздела
└── index.php                    # Главная страница
```

Состав папок зависит от редакции продукта, установленных модулей и решения. Пример показывает основные элементы, но не требует создавать все перечисленные папки в каждом проекте.

## Папка /bitrix {#bitrix}

Папка `/bitrix/` содержит системные файлы. Не изменяйте ее модули, компоненты, шаблоны и другие файлы ядра. Для собственного кода используйте [`/local/`](#local), а для изменения системного поведения — поддерживаемые механизмы [кастомизации](./how-customize.md#where-to-place-changes).

Состав папок внутри `/bitrix/` зависит от редакции продукта. Некоторые папки добавляют установленные модули.

### Основные системные каталоги и файлы

-  `/bitrix/activities/` — действия для бизнес-процессов.

-  `/bitrix/admin/` — административные скрипты.

-  `/bitrix/components/` — системные и ранее добавленные пользовательские компоненты. Новые собственные компоненты размещайте в `/local/components/`.

-  `/bitrix/css/` — общие стили модулей.

-  `/bitrix/gadgets/` — гаджеты.

-  `/bitrix/js/` — JavaScript-файлы.

-  `/bitrix/modules/` — модули системы. У каждого модуля своя структура.

-  `/bitrix/php_interface/` — служебные файлы:

   -  `init.php` — подключение пользовательских обработчиков событий. Новый код размещайте в `/local/php_interface/init.php`. Порядок подключения описан в [таблице правил загрузки](#load-rules).

   -  `dbconn.php` — файл совместимости с константами и настройками отладки. Ядро ищет его сначала в `/local/php_interface/`, затем в `php_interface/` папки из константы `BX_PERSONAL_ROOT`, по умолчанию `/bitrix/php_interface/`. Параметры соединения с базой данных ядро берет из `.settings.php`, а не из этого файла. Порядок подключения описан в статье [Жизненный цикл запроса](../framework/request-lifecycle.md).

   -  `after_connect.php` — скрипт, который использовался для настройки соединения с БД через объект `$DB`. При загрузке пролога ядро больше не подключает этот файл. Для настройки соединения используйте `after_connect_d7.php`.

   -  `after_connect_d7.php` — скрипт, который ядро D7 выполняет после подключения к БД. Порядок поиска файла описан в [таблице правил загрузки](#load-rules).

   -  `dbconn_error.php` — страница, которую ядро показывает при ошибке подключения к базе данных. Ядро ищет этот файл только в `php_interface/` папки из константы `BX_PERSONAL_ROOT`, по умолчанию `/bitrix/php_interface/`. Папку `/local/` для него ядро не проверяет.

   -  `<ID сайта>/init.php` — подключение пользовательских обработчиков событий для конкретного сайта. В административном разделе без заранее заданного `SITE_ID` вместо ID сайта используется код языка интерфейса. Порядок подключения описан в [таблице правил загрузки](#load-rules).

-  `/bitrix/.settings.php` — основная конфигурация ядра. Структура файла описана в статье [Конфигурация ядра](../framework/settings.md).

-  `/bitrix/header.php` — стандартная шапка сайта.

-  `/bitrix/footer.php` — стандартный подвал сайта.

-  `/bitrix/license_key.php` — лицензионный ключ.

-  `/bitrix/.access.php` — права доступа. Система генерирует файл автоматически.

-  `/bitrix/spread.php` — файл Главного модуля для переноса cookies посетителя на дополнительные домены различных сайтов.

-  `/bitrix/routing_index.php` — входная точка [роутинга](../framework/routing.md).

### Кеш

-  `/bitrix/cache/` — кешированные данные.

-  `/bitrix/stack_cache/` — кеш с вытеснением.

-  `/bitrix/managed_cache/` — управляемый кеш.

### Дизайн и шаблоны

-  `/bitrix/templates/` — шаблоны сайтов и компонентов:

   -  `/bitrix/templates/.default/` — файлы шаблона по умолчанию.

   -  `/bitrix/templates/<ID шаблона>/` — кастомизированный шаблон:

      -  `/bitrix/templates/<ID шаблона>/components/` — шаблоны компонентов.

      -  `/bitrix/templates/<ID шаблона>/lang/` — языковые файлы.

      -  `/bitrix/templates/<ID шаблона>/images/` — изображения шаблона.

      -  `/bitrix/templates/<ID шаблона>/page_templates/` — шаблоны страниц. Описание в `.content.php`.

      -  `header.php` — шапка сайта.

      -  `footer.php` — подвал сайта.

      -  `template_styles.css` — основные стили.

      -  `styles.css` — стили для визуального редактора.

-  `/bitrix/themes/` — темы административного раздела.

## Папка /local {#local}

Папка `/local/` предназначена для собственного кода и доработок проекта. Она отделяет файлы разработчика от системных файлов в `/bitrix/`. Если папки `/local/` нет в корне сайта, создайте ее.

### Что можно хранить

Размещайте в `/local/` те же типы файлов, для которых система поддерживает эту папку:

-  `/local/activities/` — действия бизнес-процессов.

-  `/local/components/` — собственные компоненты.

-  `/local/gadgets/` — гаджеты рабочего стола.

-  `/local/modules/` — собственные модули. Структуру модуля и порядок его создания описывает статья [Создание модуля](./create-module.md).

-  `/local/php_interface/init.php` — небольшой код инициализации проекта, например регистрация обработчиков событий. Не размещайте в нем основную бизнес-логику, классы и интеграции. Их место — в собственном модуле. Порядок подключения описан в статье [Жизненный цикл запроса](../framework/request-lifecycle.md).

-  `/local/php_interface/<ID сайта>/init.php` — код инициализации конкретного сайта. Ядро выбирает папку по значению `SITE_ID`. В административном разделе без заранее заданного `SITE_ID` вместо ID сайта используется код языка интерфейса.

-  `/local/php_interface/user_lang/<код языка>/lang.php` — замена фраз из системных языковых файлов. Файл заполняет массив `$MESS`. Ключ массива — путь к исходному языковому файлу от корня сайта, значение — массив фраз этого файла с новыми текстами. Если файла нет в `/local/`, ядро ищет его в `/bitrix/php_interface/user_lang/`. Собственные языковые файлы модулей и компонентов храните в папке `lang/` модуля или компонента.

   **Пример.** Файл `/local/php_interface/user_lang/ru/lang.php` заменяет одну фразу системного языкового файла:

   ```php
   <?php
   $MESS['/bitrix/modules/main/lang/ru/public/top_panel.php']['top_panel_tab_view'] = 'Просмотр страницы';
   ```

-  `/local/templates/` — шаблоны сайта и компонентов.

-  `/local/blocks/` — блоки Сайтов24.

-  `/local/routes/` — файлы маршрутов. Настройка описана в разделе [Конфигурация роутинга](../framework/routing.md#configuration).

-  `/local/js/<пространство имен>/<имя расширения>/` — собственные JS-расширения. Их подключает метод `Bitrix\Main\UI\Extension::load()`, порядок описан в статье [Расширения](../framework/extensions.md). Произвольный скрипт в этой папке автоматически не подключается.

-  `/local/.settings.php` и `/local/.settings_extra.php` — основная и дополнительная конфигурация ядра. Правила загрузки описаны в статье [Конфигурация ядра](../framework/settings.md).

### Как система выбирает файлы из /local и /bitrix {#load-rules}

Правило выбора зависит от типа файла. Не считайте, что любой файл из `/local/` автоматически заменяет одноименный файл из `/bitrix/`.

| Файл | Правило загрузки |
|---|---|
| `init.php` | Ядро подключает `/local/php_interface/init.php`. Если его нет, подключает `/bitrix/php_interface/init.php`. Одновременно оба общих файла не загружаются. Если константа `BX_PERSONAL_ROOT` переопределена, вместо `/bitrix/` ядро проверяет папку из этой константы. Перед ним ядро по тому же правилу подключает корневой файл `/local/init.php` или `/bitrix/init.php`, если он есть. Новый код размещайте в `/local/php_interface/init.php` |
| `<ID сайта>/init.php` | Ядро выбирает файл независимо от общего `init.php`. Сначала проверяет `/local/php_interface/<ID сайта>/init.php`, затем `/bitrix/php_interface/<ID сайта>/init.php`. Сайтовый файл подключается после общего. Общий файл может загружаться из `/local/`, а сайтовый — из `/bitrix/` |
| Компонент, шаблон сайта или компонента, модуль, JS-расширение | Если одноименный объект есть в `/local/`, ядро использует его. Иначе берет объект из `/bitrix/`. Шаблоны компонентов ищутся по отдельному порядку, описанному в статье [Компоненты](../framework/components.md#template-search) |
| `after_connect_d7.php` | После установления соединения ядро подключает первый найденный файл. Если в соединении `default` секции `connections` файла `.settings.php` задан ключ `include_after_connected`, подключается указанный в нем файл. Иначе ядро проверяет `php_interface/after_connect_d7.php` в папке из `$_SERVER['BX_PERSONAL_ROOT']`, если она задана, затем в `/local/`, затем в `/bitrix/` |
| `.settings.php` | Файл `/local/.settings.php` целиком заменяет `/bitrix/.settings.php` и должен содержать полную обязательную конфигурацию, включая секцию `connections`. Настройки двух основных файлов не объединяются |
| `.settings_extra.php` | Система сначала ищет файл в `/local/`, затем в `/bitrix/` и подключает только первый найденный. Дополнительный файл загружается после основного и заменяет одноименные секции целиком |
| `routes/web.php` | Если `web.php` указан в настройке `routing.value.config`, система подключает сначала `/local/routes/web.php`, затем `/bitrix/routes/web.php`. Если существуют оба файла, загружаются оба. Из значения настройки система берет только имя файла, поэтому подпапки и полные пути не работают. Собственные маршруты размещайте только в `/local/routes/` |

При переносе `init.php` из `/bitrix/php_interface/` в `/local/php_interface/` сохраните нужный код прежнего файла. Иначе регистрация обработчиков событий и другая логика инициализации перестанут выполняться.

Подробности о загрузке конкретного типа файла приведены в статьях [Жизненный цикл запроса](../framework/request-lifecycle.md), [Конфигурация ядра](../framework/settings.md) и [Роутинг](../framework/routing.md#configuration).

Для папки `/local/php_interface/` установите такие же права доступа, как для `/bitrix/php_interface/`. Она содержит файлы, которые ядро выполняет при инициализации.

### Как перенести доработки из /bitrix в /local {#migrate-to-local}

1. Создайте [резервную копию](../advanced/backup.md) и проверьте доработки на копии сайта.

2. Найдите измененные файлы ядра через *Монитор качества* в административном разделе на странице *Настройки > Инструменты > Монитор качества*.

3. Создайте нужную структуру папок в `/local/` и перенесите собственный код. Для файлов из таблицы выше учитывайте правила их загрузки.

4. Проверьте обработчики событий, настройки, маршруты и публичные страницы после каждого переноса.

## Папка /upload {#upload}

Папка `/upload/` хранит файлы, которые загружают на сайт стандартные механизмы Bitrix Framework. Это не папка для собственных PHP-скриптов, модулей и шаблонов. Такой код размещайте в `/local/` или в публичных разделах сайта.

Вместо `/upload/` можно указать другую папку в настройках Главного модуля.

1. Откройте в административном разделе страницу *Настройки > Настройки продукта > Настройки модулей > Главный модуль*.

2. Укажите папку в поле *Папка по умолчанию для загрузки файлов*. После изменения настройки стандартные механизмы будут использовать новый путь.

Перед сменой папки перенесите существующие файлы с сохранением структуры подпапок. Система формирует URL ранее загруженных файлов с текущим значением настройки `upload_dir`, но не переносит содержимое старой папки автоматически.

### Как хранятся файлы

Система автоматически создает подпапки для разных типов контента, например:

-  `/upload/resize_cache/` — кешированные версии изображений после обработки,

-  `/upload/iblock/` — файлы инфоблоков,

-  `/upload/medialibrary/` — файлы медиабиблиотеки.

Каждый модуль может создавать свои подпапки для хранения файлов.

### Как работать с файлами {#working-with-files}

Используйте стандартные инструменты для каждого сценария:

-  медиабиблиотеку — для изображений, аудио, видео и документов,

-  файловый менеджер — для работы с файлами в административном разделе,

-  файловый API — для загрузки, получения и удаления файлов в коде.

Для доступа к файлам из кода используйте методы API вместо прямого чтения и записи по путям в `/upload/`. Метод `CFile::SaveFile($arFile, $strSavePath)` сохраняет файл и регистрирует его в хранилище. Передайте в метод два обязательных аргумента:

-  `$arFile` — массив файла в формате `$_FILES` с ключами `name`, `type`, `tmp_name`, `size` или с ключом `content` вместо `tmp_name`,

-  `$strSavePath` — подпапка внутри папки загрузки, например `my.module`. Система добавит к ней служебную подпапку, и файл попадет в `/upload/my.module/<служебная подпапка>/`.

Необязательные аргументы `$forceRandom`, `$skipExtension` и `$dirAdd` управляют случайным именем файла, расширением и подпапкой. Аргумент `$dirAdd` действует, только если в модуле `main` включено сохранение исходного имени — опция `save_original_file_name` равна `Y` — и `$forceRandom` равен `false`.

Чтобы файл был привязан к модулю, передайте в `$arFile` ключ `MODULE_ID`. Аргумент `$strSavePath` задает только папку и модуль не определяет.

Если в настройках модуля `main` включен контроль дубликатов — опция `control_file_duplicates` равна `Y` — и размер файла не превышает значение `duplicates_max_size` в мегабайтах, система не создает копию уже сохраненного файла. Новая запись ссылается на существующий файл. При установке продукта контроль дубликатов включается. Если опция не задана, контроль выключен. Значение `duplicates_max_size` по умолчанию — 100. Значение `0` снимает ограничение по размеру.

При успешном сохранении метод возвращает целочисленный идентификатор файла, при ошибке — `false`. Если ключ `name` пустой, метод тоже возвращает `false` и ничего не сохраняет. Имя файла на диске метод нормализует, а исходное имя сохраняет в поле `ORIGINAL_NAME`. Сохраните идентификатор в данных своего объекта. Связь файла с объектом формирует вызывающий код. Обработчик события `OnFileSave` может изменить способ физического хранения файла. Примеры использования описаны в статье [Обработка изображений](../advanced/images.md).

Перед сохранением проверьте, что файл загрузился без ошибок, а его размер и расширение допустимы. Метод `CFile::CheckFile($arFile, $intMaxSize, $mimeType, $strExt)` возвращает пустую строку, если файл прошел проверку, или текст ошибки. Аргументы метода:

-  `$arFile` — массив файла в формате `$_FILES`,
-  `$intMaxSize` — максимальный размер в байтах, `0` — без ограничения,
-  `$mimeType` — строка или массив начальных частей MIME-типа, например `'image/'`. `false` отключает проверку типа,
-  `$strExt` — допустимые расширения через запятую без точки, регистр не учитывается. `false` отключает проверку расширения.

Если имя файла пустое, метод возвращает пустую строку, как для корректного файла. Поэтому сначала проверьте, что `$arFile['error']` равен `UPLOAD_ERR_OK`.

**Пример.** Метод контроллера или компонента сохраняет файл из поля формы `DOCUMENT` в подпапку модуля и возвращает его идентификатор:

```php
private function saveDocument(): ?int
{
    $file = \Bitrix\Main\Context::getCurrent()->getRequest()->getFile('DOCUMENT');
    if (!is_array($file) || $file['error'] !== UPLOAD_ERR_OK)
    {
        // Файл не загружен
        return null;
    }

    // Не больше 5 Мб, только PDF и DOCX
    $error = \CFile::CheckFile($file, 5 * 1024 * 1024, false, 'pdf,docx');
    if ($error !== '')
    {
        // Файл не прошел проверку, текст ошибки в $error
        return null;
    }

    $file['MODULE_ID'] = 'my.module';

    $fileId = \CFile::SaveFile($file, 'my.module');
    if ($fileId === false)
    {
        // Файл не сохранен
        return null;
    }

    // Сохраните $fileId в поле своего объекта, например DOCUMENT_ID
    return (int)$fileId;
}
```

## Публичные страницы и разделы {#public}

Публичные файлы размещают в корне сайта и его разделах, а не в `/local/`. Структура публичной части зависит от установленного решения и настроек.

**Главная страница**. Файл `/index.php` находится в корне сайта и открывает его главную страницу.

**Страницы**. PHP-файлы содержат код и контент страниц. Их размещают в файловой структуре сайта. Порядок создания и подключения шаблона описан в статье [Создание страницы](./create-page.md).

**Разделы**. Папки группируют страницы. Индексный файл раздела, например `/catalog/index.php`, формирует его главную страницу.

{% note info "" %}

Контент на сайте может формироваться динамическими страницами и разделами. Их нет в файловой структуре. Они виртуальные, то есть их генерирует код.

Например, в файле `/catalog/index.php` можно разместить компонент, который создаст структуру из разделов и страниц с товарами на сайте.

{% endnote %}

## Как выбрать папку для нового файла

Определите назначение файла и используйте соответствующий путь. Не выбирайте папку только по расширению, потому что PHP-файл может быть частью модуля, обработчиком инициализации или публичной страницей.

| Что нужно добавить | Куда поместить | Результат |
|---|---|---|
| Собственный модуль | `/local/modules/<ID модуля>/` | Код модуля отделен от системных файлов в `/bitrix/modules/` |
| Собственный компонент | `/local/components/<пространство имен>/<имя компонента>/` | Компонент хранится в области доработок проекта |
| Регистрацию обработчика событий | `/local/php_interface/init.php` | Ядро подключает обработчик при инициализации проекта |
| Шаблон сайта | `/local/templates/<ID шаблона>/` | Шаблон находится отдельно от системных шаблонов |
| Маршруты | `/local/routes/web.php` или другой файл в папке `/local/routes/`, имя которого указано в настройке `routing.value.config` | Роутер загружает маршруты проекта |
| Физическую страницу или раздел | `/<раздел>/index.php` или другой PHP-файл в публичной структуре | Страница доступна по адресу, который соответствует ее расположению и настройкам обработки URL |
| Загружаемый пользователем файл | Файловое хранилище через стандартный интерфейс или [`CFile::SaveFile()`](#working-with-files) | Файл лежит в подпапке `/upload/`, а вызывающий код хранит его идентификатор в данных объекта |

После размещения собственного кода перейдите к инструкциям [Создание компонента](./create-component.md), [Создание модуля](./create-module.md) или [Создание страницы](./create-page.md). Для обработки URL используйте [роутинг](../framework/routing.md), а для изменения системного поведения — [события](../framework/events.md).
